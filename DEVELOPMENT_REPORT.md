# FASULYE Opportunity Engine 3.0 — Development report

Date: 2026-11-27. Branch: `feature/panel-session-ux`. Status: implementation in progress; production merge not yet approved by checks.

## Findings
V2 queue used one search order, 365-day window and one 25-result page. Search region/relevanceLanguage are query parameters, not viewer geography; duration alone cannot verify Shorts. Public subscriber counts are current, not historical at upload. Descriptions/categories were missing; independently sourced search volume is unavailable. Summed cross-channel views are removed from new reports and presentation, not substituted with a score.

## Implemented
- SQL migrations in `engine/tools/opportunity_engine/supabase/{login_audit,query_profiles,production_costs}.sql` applied to the specified project. Catalog 3 snapshot stored and read back: 14 categories, 8 priority markets. Legacy catalog and report format preserved.
- Queue search profiles: 7/30/90/365 days, relevance/date/viewCount, 50 results maximum per queued call, two natural variants per category/language in priority markets. Four profiles × 8 markets × 10 categories = 320 requested calls; daily reservation remains 30, worker 10 tasks per execution. Existing retry/lease and deduplication mechanisms retained. Same-day identical batch deduplication; cross-batch individual query cache still missing.
- Raw metadata, current subscriber count, dates, duration filter, description excerpt and declared language. Unverified semantic relevance and Shorts kept explicit. Small-channel latest uploads: up to two channels, 25 public uploads each; no derived performance score. Source-independent editorial assessment retained.
- Source provenance on RPM assumptions, actual cost input table, independent pre-tax profit scenarios with same-currency constraint. 72 existing RPM rows checked: 55 third-party model, 17 third-party sample. Source dates missing where not established; no invented production costs. Trends CSV remains available. Google Ads Keyword Planner applicability researched from official docs; no live credential/onboarding or absolute YouTube volume claim.
- Login screen uses existing Netlify panel password; 90-day remembered browser cookie; separate admin unlock for login event table; optional label, pseudonymous browser ID, browser/OS and timestamp, no password/IP logging. Cookie session does not depend on audit DB availability. Old MCP bearer remains compatible. Focused page navigation, country/language names, deep campaign preview, channel library and cost controls.
- Tests added for cookie expiry/rotation, admin separation, CSRF, campaign plan (320 tasks), profit inputs and currency mismatch. README updated.

## Outstanding / limitations
- Final CI, live 3.0 YouTube request and end-to-end dashboard/MCP/Netlify authenticated tests. Full 320-task campaign not submitted because production still runs V2, which would ignore new task profiles; must only enqueue after V3 worker deployment. No market conclusions without real new research and independent demand evidence.
- Netlify last verified env metadata contains FASULYE_ACCESS_TOKEN and FASULYE_GITHUB_TOKEN only; SUPABASE_SECRET_KEY and separate FASULYE_ADMIN_TOKEN must be configured by owner, never pasted in source. Login audit cannot save/read until the DB credential works; browser login unit tests alone are not production authentication verification. Shared password does not identify individuals.
- Automated semantic content/suitability classification, automated cross-language discovery of novel ideas, independent corroborated market-specific recommendations, universal natural translation, and durable cross-report channel library not complete. Manual examination of raw metadata and independent evidence is supported. Shorts classification cannot be verified from duration alone. The 8-market four-window profile mixes query text and order, so window differences cannot establish trends or causality. Need controlled same-query repeated profiles for strict comparison.
- Google Trends Alpha approval pending. Google Ads access not configured. No new paid service used, no fake research data inserted.
